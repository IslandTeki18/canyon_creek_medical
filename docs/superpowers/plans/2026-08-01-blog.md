# Blog Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the static placeholder journal (`src/features/public/blog-page.tsx`) with a staff/admin-authored `blogPosts` feature, including new public post detail pages at `blog/:slug`.

**Architecture:** One new Convex table `blogPosts` (draft/published/archived) in `convex/domains/blog.ts`, gated by a **new capability `content.author`** granted to frontDesk, clinicalStaff, provider, and administrator. Bodies are plain text rendered as paragraphs (no editor or markdown dependency). Two unauthenticated public queries serve published posts, registered in the authorization-matrix exemption list. The public blog page swaps its literals for queries and gains a detail route.

**Tech Stack:** Convex, zod 4, React 19 + react-router 8, Tailwind, convex-test + Vitest (edge-runtime).

**Dependency:** Independent of the service-pages plan, except both add entries to `NOTICE_PREFIXES` (`"content."` — add once) and both create new domain files. If service-pages lands first, reuse its `"content."` audit prefix; nothing else is shared.

---

## Decisions and constraints (read first)

- **"Staff and admins":** there is no `staff` role. New capability `content.author` in `convex/lib/permissions.ts`, granted to `frontDesk`, `clinicalStaff`, `provider`, `administrator`. Authorization checks the capability, never role labels. `patient` and `auditor` do not get it.
- **Authoring model:** any `content.author` holder can create, edit, publish, unpublish, and archive **any** post (small clinic, collaborative editing; per-author ownership is speculative). Administrators have no extra blog powers. `// ponytail: no per-author ownership; add an ownership check if authorship disputes ever matter.`
- **Body format:** plain text; the renderer splits on blank lines into `<p>` elements. No markdown dependency, no HTML storage (no sanitization surface). Upgrade path: swap the renderer for a markdown library; stored bodies remain valid.
- **Author display name is a stored string** (`authorName`), defaulted in the UI from the logged-in user's display name but editable — posts may be bylined "Canyon Creek Team". The internal `createdByUserId` is recorded for audit but **never returned by public queries**.
- **Categories:** fixed list matching the current page: `"Mental health" | "Addiction medicine" | "Holistic care" | "Practice news"`. A union validator, not a table. `// ponytail: hardcoded category union; make it a table if categories become editable.`
- **Read time** is computed at render time (`Math.max(1, Math.round(words / 200))` min), not stored.
- **Featured post** = most recently published. No flag. `// ponytail: newest-is-featured; add a featured flag if editorial control is requested.`
- **No PHI:** blog copy is operator-authored marketing/education content. The editor page includes a static reminder: never reference identifiable patients. Slugs appear in URLs by design and must contain no PHI.
- **Search/pagination out of scope** for v1 — the clinic will have a handful of posts. Public list returns all published posts sorted by `publishedAt` desc. Upgrade path: `searchIndex` like `patients.search`, `paginate()`.
- **Newsletter form** on the blog page stays UI-only (out of scope; would need Resend + consent handling).
- **Soft delete only:** archive with reason; never hard delete.
- **Audit actions:** `content.blogPost.created|updated|published|unpublished|archived` under the `"content."` notice prefix.

```ts
function toPublicPost(doc: Doc<"blogPosts">) {
  const { slug, title, category, excerpt, body, authorName, publishedAt } = doc;
  return { slug, title, category, excerpt, body, authorName, publishedAt };
}

export const listPublishedPosts = query({
  args: {},
  handler: async (ctx) => {
    const posts = await ctx.db
      .query("blogPosts")
      .withIndex("by_status_published", (q) => q.eq("status", "published"))
      .order("desc")
      .collect();
    return posts.map(toPublicPost);
  },
});

export const getPublishedPost = query({
  args: { slug: v.string() },
  handler: async (ctx, { slug }) => {
    const post = await ctx.db
      .query("blogPosts")
      .withIndex("by_slug", (q) => q.eq("slug", slug))
      .unique();
    return post && post.status === "published" ? toPublicPost(post) : null;
  },
});
```

- Per-author ownership/approval workflow (any `content.author` holder edits anything).
- Newsletter signup backend, comments, RSS, SEO meta tooling.
- Draft preview links for unauthenticated reviewers.
